## О проекте

`setup.sh` - Bash-скрипт для первичной настройки чистого VPS. Он обновляет систему, настраивает SSH, firewall и Fail2ban, управляет swap, включает необходимые системные параметры и при необходимости устанавливает Docker.

> [!IMPORTANT]
> Скрипт изменяет SSH, firewall и системные конфигурации. Не закрывайте текущую SSH-сессию до завершения проверки нового подключения. Перед использованием на production-сервере рекомендуется создать snapshot.

## Возможности

- Обновление системы и установка базовых утилит;
- Автоматический запуск внутри `tmux`;
- Добавление публичного SSH-ключа;
- Безопасная смена SSH-порта с проверкой и откатом;
- Отключение входа по паролю только после проверки ключа;
- Настройка UFW и Fail2ban;
- Включение IPv4 forwarding и BBR при поддержке ядром;
- Ограничение журналов systemd;
- Создание или изменение `/swapfile`;
- Установка Docker Engine и Docker Compose Plugin;
- Логирование и резервное копирование изменяемых конфигураций.

Каждый основной этап можно пропустить.


## Быстрый старт

Скопировать команду и выполнить в терминале с root доступом:

```bash
curl -fsSLo setup.sh https://raw.githubusercontent.com/RandomAlex123/vps-setup/main/setup.sh
chmod +x setup.sh
./setup.sh
```

`curl` скачивает файл: `-f` завершает команду ошибкой при HTTP-ошибке, `-s` скрывает индикатор загрузки, `-S` оставляет сообщения об ошибках, `-L` следует перенаправлениям, `-o setup.sh` задаёт имя файла. `chmod +x` добавляет право выполнения, `./setup.sh` запускает файл из текущего каталога. Эти команды выполняются на Linux VPS.

## Что настраивает скрипт

### Обновление системы

Скрипт обновляет список пакетов, устанавливает доступные обновления и добавляет базовые утилиты для администрирования сервера:

- `curl`, `wget`, `git`, `jq`;
- `zip`, `unzip`, `tar`, `rsync`;
- `openssl`, `gnupg`, `ca-certificates`;
- `iproute2`, `dnsutils`, `socat`;
- `cron`, `logrotate`, `sudo`, `kmod`;
- OpenSSH Server и OpenSSH Client;
- UFW, Fail2ban и unattended-upgrades.

### Автоматические обновления безопасности

При подтверждении включается автоматическая установка обновлений безопасности:

- Ежедневное обновление списка пакетов;
- Автоматическая установка security-обновлений;
- Очистка кэша пакетов раз в 7 дней;
- Автоматическая перезагрузка сервера отключена.

### SSH

Если ключа ещё нет, создайте его в **Git Bash на локальном компьютере, не на VPS**:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -C "vps-access"
cat ~/.ssh/id_ed25519.pub
```

`ssh-keygen` создаёт пару ключей, `-t ed25519` выбирает алгоритм Ed25519, `-f ~/.ssh/id_ed25519` задаёт путь к приватному ключу, `-C` задаёт комментарий для распознавания ключа. Публичный ключ сохраняется рядом с окончанием `.pub`. Задайте парольную фразу для защиты приватного ключа. Если файл уже существует, не перезаписывайте его: используйте существующий ключ или измените путь после `-f`.

`cat` выводит содержимое файла, `~` означает домашний каталог локального пользователя. Если выбрано другое имя ключа, укажите соответствующий файл с окончанием `.pub`. Полученную строку целиком вставьте в запрос `Paste one public key line`. Файл без `.pub` — приватный ключ; его содержимое на сервер не передаётся.

Скрипт может:

- Добавить публичный SSH-ключ выбранному пользователю;
- Изменить стандартный SSH-порт;
- Сохранить исходные IP-адреса и семейства прослушивания при смене порта, включая `ssh.socket`;
- Временно сохранить старый порт до завершения проверки;
- Проверить, что новые SSH-порты действительно прослушиваются;
- Разрешить новый порт в UFW, если firewall уже активен;
- Отключить вход по паролю только после успешного входа по ключу;
- Проверить фактический запрет паролей и keyboard-interactive, а также повторный вход по ключу после изменения;
- Удалить старый SSH-порт после подтверждения;
- Автоматически откатить незавершённые изменения при ошибке.

До отдельного подтверждения текущая SSH-сессия и старый способ подключения сохраняются.

Ключ записывается с правами выбранного пользователя. Символические ссылки в `.ssh` и `authorized_keys`, а также файл ключей с несколькими жёсткими ссылками отклоняются. Существующий файл ключей копируется в `.ssh/authorized_keys.setup-backup-<дата-и-время>` с правами пользователя. При откате серверной конфигурации добавленный ключ сохраняется; домашний каталог пользователя от root не восстанавливается.

Исходные адреса SSH считываются из действующей конфигурации. Socket-режим выбирается только для активного `ssh.socket`; включённый, но остановленный сокет не запускается вместо работающего SSH-сервиса. При промежуточной проверке старые адреса и порты сохраняются, новый порт добавляется на тех же адресах. Перед перезагрузкой SSH проверяется полный набор адресов и портов. При добавлении одного ключа настройки `ssh.socket` не переписываются. Неизвестные форматы listener-ов (например, Unix-сокет) отклоняются до изменений; противоречащие настройки из дополнительных include-файлов вызывают откат. Локальная проверка использует адрес реально слушающего сокета, а не обязательно `127.0.0.1`.

При отключении паролей управляемые глобальные параметры ставятся перед существующими настройками; их итоговые значения проверяются через `sshd -T`. Скрипт обходит весь граф `Include` и отказывается от автоматического отключения, если встречает условное разрешение паролей или keyboard-interactive в `Match`, рекурсивные include-файлы, обратные слеши в include-пути либо неподдерживаемое расширение пути. Такие исключения необходимо сначала разобрать вручную. Настройки `Match` без повторного разрешения этих методов сохраняются.

В socket-режиме слушающий сокет и master-процесс SSH останавливаются одной транзакцией systemd, затем запускается сокет и при необходимости новый master, получающий актуальные дескрипторы. Это исключает повторную активацию со старыми дескрипторами между остановкой master и обновлением сокета. Обычный `reload` здесь не используется: на Debian 13 он может потерять унаследованные сокеты. Перед изменениями проверяется `KillMode=process`, чтобы остановка master не завершала уже установленные клиентские сеансы. Другой режим завершения процессов отклоняется до настройки. Если сервис изначально не работал, сохраняется запуск по обращению к сокету; при откате учитывается исходное состояние сервиса.

Проверочная команда SSH запрещает парольный fallback и повторное использование старого соединения. В ней `ssh` — клиент Secure Shell; `-F /dev/null` исключает клиентские конфигурационные файлы, `-S none` отключает использование control socket, `-o` задаёт именованную опцию. `IdentitiesOnly=yes` ограничивает предлагаемые ключи указанными identity-файлами, `PreferredAuthentications=publickey` выбирает вход по ключу, `PasswordAuthentication=no` и `KbdInteractiveAuthentication=no` запрещают альтернативные парольные методы. `-i` указывает локальный приватный ключ, `-p` — порт сервера. Парольная фраза приватного ключа может запрашиваться локально: это не пароль учётной записи сервера. После применения окончательных настроек требуется ещё одно новое подключение и подтверждение; при отказе серверная конфигурация откатывается.

### UFW

При подтверждении скрипт:

- Устанавливает UFW;
- Запрещает все входящие подключения по умолчанию;
- Разрешает все исходящие подключения;
- Добавляет разрешения для текущих SSH-портов;
- По умолчанию сохраняет существующие правила и предупреждает, что другие порты могут остаться открытыми;
- По отдельному подтверждению заменяет правила UFW разрешениями только для SSH и запрещает пересылаемый трафик;
- Проверяет наличие разрешающих правил после включения firewall;
- Восстанавливает предыдущие правила, если настройка завершилась ошибкой.

В режиме замены удаляются также старые правила приложений и маршрутизации UFW: существующий VPN или другие сервисы могут потерять доступ. Перед изменением сохраняется весь каталог `/etc/ufw` и `/etc/default/ufw`; при проверяемой ошибке восстанавливаются конфигурация и предыдущее состояние активности. После замены проверяется полный набор пользовательских правил UFW.

Другие порты скрипт не открывает. Сохранение старых правил не означает, что другие порты закрыты. Правила Docker и firewall провайдера проверяются отдельно; UFW содержит также стандартные системные правила, например для ICMP.

### Fail2ban

Fail2ban настраивается для защиты SSH:

- Используется jail `sshd`;
- Backend — `systemd`;
- Учитываются все активные SSH-порты;
- После 5 неудачных попыток адрес блокируется на 1 час;
- Попытки учитываются за интервал 10 минут;
- Текущий IP можно добавить в список исключений;
- Предыдущая конфигурация восстанавливается при неудачном запуске.

### Системные параметры и BBR

Скрипт может настроить:

- IPv4 forwarding;
- IPv6 forwarding по отдельному подтверждению;
- Очередь `fq`;
- TCP congestion control `bbr`, если он поддерживается текущим ядром.

Настройки записываются в отдельный файл в `/etc/sysctl.d/` и проверяются после применения. При ошибке предыдущая конфигурация восстанавливается.

### Журналы systemd

При подтверждении настраиваются ограничения journald:

- Максимальный размер постоянных журналов — 200 МБ;
- Максимальный размер runtime-журналов — 100 МБ;
- Максимальный срок хранения — 14 дней.

После применения выполняется очистка старых журналов.

### Swap

Скрипт:

- Отображает существующий swap, размер `/swapfile` и общий объём swap;
- Позволяет создать или изменить `/swapfile`;
- Принимает размер от 128 до 131072 МБ;
- Корректно отключает старый `/swapfile` перед заменой;
- Добавляет `/swapfile` в `/etc/fstab`;
- Восстанавливает старый swap-файл при ошибке активации или обновления `/etc/fstab`.

Существующие swap-разделы не удаляются.

### Docker

Docker устанавливается только после отдельного подтверждения.

Скрипт:

- Добавляет официальный репозиторий Docker;
- Устанавливает Docker;
- Включает и запускает сервис Docker;
- Проверяет успешность установки.

### Логи, резервные копии и итоговая проверка

Скрипт сохраняет лог выполнения в:

```text
/var/log/setup.log
```

Резервные копии изменяемых файлов сохраняются в:

```text
/var/backups/setup/<дата-и-время-запуска>/
```

## tmux

Скрипт автоматически устанавливает `tmux` и продолжает работу в сессии `vps-setup`.

Для повторного подключения к сессии:

```bash
tmux attach -t vps-setup
```

`tmux` — терминальный мультиплексор, сохраняющий сеанс при разрыве SSH; `attach` подключается к существующей сессии, `-t vps-setup` выбирает её по имени.

## Проверка изменений

Проверка синтаксиса без выполнения настройки и изолированные регрессионные тесты:

```bash
bash -n setup.sh
python3 tests/security_regressions.py
```

`bash -n` разбирает синтаксис скрипта, не выполняя его. `python3` запускает тестовый файл: тесты извлекают отдельные функции, работают во временных каталогах и подменяют команды управления сервисами/firewall. На Linux при запуске тестов от root дополнительно проверяется настоящая граница прав через существующего пользователя `nobody`. Полный `setup.sh` тесты не запускают.

В Git Bash на Windows вместо второй команды можно использовать:

```bash
TEST_BASH='C:/Program Files/Git/bin/bash.exe' python tests/security_regressions.py
```

Присваивание `TEST_BASH=...` выбирает исполняемый файл Bash только для этой команды; `python` запускает установленный Python. На Windows проверки настоящих символических ссылок и смены Linux UID могут быть явно пропущены. Эти тесты не заменяют проверку SSH/UFW/systemd на отдельной Linux VM с доступом к консоли.

## Предупреждение

Перед запуском изучите исходный код и убедитесь, что у вас есть доступ к web-консоли или rescue mode. Ответственность за итоговую конфигурацию и безопасность сервера остаётся за администратором.
